# Ассистент проверки коммуникаций

Проверяет материал по базе внутренних требований — Legal, PR, GR, коммуникационная стратегия —
и возвращает заключение: вердикт, находки с цитатами и рекомендации.

Здесь всё, чтобы поднять его по ссылке для команды. **Коллегам не нужен ни аккаунт Claude,
ни ключ** — только адрес и пароль.

---

## Что внутри

```
server.js           сервер: страница + прокси к модели + журнал прогонов
public/index.html   сам инструмент, база из 44 правил вшита в файл
Dockerfile          для Docker и Fly
render.yaml         для Render
fly.toml            для Fly.io
docker-compose.yml  для любой виртуалки с Docker
.env.example        шаблон переменных
```

Зависимостей нет. Нужен Node 18+ или Docker.

---

## Куда захостить

### Внутренний сервер компании — правильный вариант

Любая виртуалка, где есть Node или Docker. Единственный способ работать с настоящими
внутренними материалами: ставите `ANTHROPIC_BASE_URL` на внутренний гейтвей — и наружу
не уходит ничего.

```bash
export ANTHROPIC_API_KEY=sk-ant-...
export ACCESS_PASSWORD=пароль-для-команды
node server.js                       # или: docker compose up -d
```

### Render — быстрее всего, если контур не нужен

1. Залить папку в репозиторий
2. Render → New → Web Service → выбрать репозиторий
3. В Environment добавить `ANTHROPIC_API_KEY` и `ACCESS_PASSWORD`
4. Получить адрес вида `https://comms-assistant.onrender.com`

`render.yaml` уже лежит рядом, остальное платформа подхватит сама.

### Fly.io — если нужен регион поближе

```bash
fly launch --no-deploy
fly secrets set ANTHROPIC_API_KEY=sk-ant-... ACCESS_PASSWORD=пароль
fly deploy
```

### Docker где угодно

```bash
cp .env.example .env && $EDITOR .env
docker compose up -d
```

> Внешний хостинг годится только для обезличенных материалов. Настоящие тексты
> инициатив и внутренние документы — исключительно во внутреннем контуре.

## Если до сервиса не достучаться

Бывает, что хостинг с моделью недоступен из корпоративной сети или у части команды.
Тогда поднимается два экземпляра одного и того же приложения:

```
человек → ближний сервер (доступный) → дальний сервер → модель
```

Ближний отдаёт страницу и пересылает запросы дальше. Ключ модели остаётся только
на дальнем — на ближнем его нет вовсе.

**Дальний сервер** (там, где доступна модель) — к обычным переменным добавить:

```bash
RELAY_ACCEPT=длинный-пароль-для-релея     # пускать только наш ближний сервер
```

**Ближний сервер** (туда заходят люди) — ключ модели не нужен:

```bash
RELAY_TO=https://адрес-дальнего-сервера
RELAY_PASSWORD=длинный-пароль-для-релея
ACCESS_PASSWORD=пароль-для-команды
```

Всё остальное работает как обычно: страница, чтение PDF, журнал прогонов.
Модель ближний сервер спрашивает у дальнего, поэтому в шапке видна настоящая.

## Переменные

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `ANTHROPIC_API_KEY` | — | Обязательна, без неё сервер не стартует |
| `ACCESS_PASSWORD` | пусто | Пароль на вход. Пусто — доступ свободный |
| `PORT` | 8080 | Порт |
| `ANTHROPIC_BASE_URL` | `https://api.anthropic.com` | Куда ходить за моделью: Anthropic напрямую, OpenRouter или внутренний гейтвей |
| `MODEL` | пусто | Подмена имени модели. Нужна для шлюзов: у них свои названия |
| `PROVIDER` | пусто | Закрепляет провайдера у шлюза. `Anthropic` — запрос не уйдёт к Bedrock или Vertex |
| `RELAY_TO` | пусто | Адрес дальнего сервера. Задан — экземпляр работает релеем и ключ модели ему не нужен |
| `RELAY_PASSWORD` | пусто | Пароль, с которым релей стучится к дальнему серверу |
| `RELAY_ACCEPT` | пусто | На дальнем сервере: пускать запросы релея с этим паролем |
| `LOG_RUNS` | включён | `0` отключает журнал |

Ключ лежит только на сервере. В странице его нет, из браузера не достать.

## Через OpenRouter

Подходит, если оплата напрямую в Anthropic неудобна. У OpenRouter есть эндпоинт
в нативном формате Anthropic Messages, поэтому код менять не нужно — только переменные:

```bash
ANTHROPIC_API_KEY=sk-or-v1-...            # ключ OpenRouter
ANTHROPIC_BASE_URL=https://openrouter.ai/api
MODEL=anthropic/claude-sonnet-4.6         # точное имя смотрите на openrouter.ai/models
PROVIDER=Anthropic                        # чтобы запрос шёл только к Anthropic
```

### Переключение на Opus

Меняется одной переменной, перезапуск подхватит её сам:

```bash
MODEL=anthropic/claude-opus-5             # точный идентификатор — на странице модели
```

Opus заметно сильнее на разборе правил и пишет более живые правки, но дороже:
5 и 25 долларов за миллион токенов против 3 и 15 у Sonnet. Одна проверка обойдётся
примерно в 15 центов вместо 8.

Модель, которая реально используется, видна в шапке инструмента — страница
запрашивает её у сервера, а не берёт из кода.

Что важно знать:

- имя модели у шлюза своё, с префиксом провайдера — сверьте на странице моделей
- регистрация через Google или GitHub, баланс пополняется кредитами
- при желании можно переключить инструмент на другую модель, поменяв одну переменную,
  но качество разбора по правилам придётся проверять заново на своих примерах

## Что получают коллеги

Открывают адрес, вводят пароль (логин любой) и работают. Аккаунт Claude не нужен,
устанавливать ничего не надо, расход идёт по вашему ключу.

Функциональность та же, что при локальном запуске: вставка текста, загрузка скриншотов,
PDF, docx и txt, распознавание вложений, заключение с находками и рекомендациями.

## Журнал прогонов

Каждый вызов пишется в `runs/ГГГГ-ММ-ДД.jsonl`: время, длительность, статус, версия модели,
текст запроса и ответ. Содержимое картинок не сохраняется — только пометка о вложении.

```bash
tail -n 5 runs/$(date +%F).jsonl | python3 -m json.tool
```

Нужен, чтобы разобрать странный ответ и собрать статистику для ретро-теста на негативных кейсах.

На платформах с эфемерным диском журнал переживает только текущий запуск. Для постоянного
хранения примонтируйте том — в `docker-compose.yml` это уже сделано.

## Почему у всех одинаковый результат

- `temperature` принудительно ставится в 0 на сервере, страница не может это переопределить
- версия модели зафиксирована в коде
- вердикт и оценки считаются арифметикой поверх находок, а не моделью

В шапке инструмента показан отпечаток базы, например `база 44 · 77f117`. Совпал у двоих —
значит правила одинаковые, и расхождение искать надо не в базе.

## Обновление правил

Правила лежат в `public/index.html` как массив `RULES`. Чтобы обновить — соберите файл заново
из YAML-исходников и замените `public/index.html`. Перезапуск не нужен, страница отдаётся
без кеша.

## Как читаются файлы

| Формат | Как обрабатывается |
|---|---|
| PDF с текстовым слоем | читается целиком прямо в браузере, к модели не уходит |
| PDF-скан, png, jpg | распознаёт модель |
| docx | распаковывается в браузере |
| txt, md | подставляется как есть |

Библиотека чтения PDF лежит в `public/vendor/` — внешняя сеть для неё не нужна.
Если папку удалить, приложение попробует CDN, а при недоступности отдаст PDF модели.

## Границы инструмента

- не заменяет согласование с PR, GR и юристами — показывает, с чем к ним идти
- проверяет только то, на что написаны требования; пустой домен виден в заключении отдельно
- база собрана под агентов и агентства недвижимости, другим вертикалям нужны свои правила
